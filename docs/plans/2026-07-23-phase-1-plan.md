# Phase 1 Implementation Plan

**Branch:** `phase-1` (not merged/deployed until approved) · 2026-07-23

**Constraints for this phase (per product owner):**
- Do NOT integrate paid **backlink data** APIs (stays Phase 3).
- Do NOT call paid **AI/LLM APIs** for now. Build the full workflow; where AI
  generation belongs, use a deterministic fallback behind a clean plug-in point
  so it works today and enables when a key is added later.
- Everything stays behind the existing password gate + noindex (not public).

## Feature 1 — Optimization Engine (mostly deterministic; build first)

Turn the report + crawled page into ready-to-apply assets the user can copy or
download. All generated from crawled data — no AI required.

- `src/lib/optimize/assets.ts` — pure `buildOptimizations(page, report): OptimizationAssets`:
  - **JSON-LD schema** — Organization + WebSite blocks from title/url/description.
  - **Meta tags** — `<title>` and `<meta name="description">` (derive from existing
    content when missing/weak; deterministic).
  - **llms.txt** — a Markdown llms.txt from title, description, and key headings.
  - **robots.txt guidance** — lines to unblock AI bots when they're disallowed.
  - Each asset: `{ key, title, whatItFixes, language, content }`.
- Tests per generator (TDD).
- `src/components/OptimizationAssets.tsx` — collapsible section on the report with
  each asset in a copy-to-clipboard code block.
- Wire into the server action success state + `ReportResults`.
- (Deferred plug-in) AI copy-rewrite — stub returning the existing copy with a note.

## Feature 2 — Content Studio

Guided Q&A → draft page grounded ONLY in user-supplied facts → 4 safety gates →
human review + approval → stored. LLM generation is a pluggable step (deterministic
template assembly for now; Claude when enabled).

- `src/lib/content/` — intake types, deterministic draft assembler, and the safety
  gates:
  1. **No fabricated facts** — draft may only use facts from the Q&A; flag/strip
     anything unsupported. (Deterministic assembler makes this natural.)
  2. **YMYL detection** — keyword classifier (medical/legal/financial) → require
     sign-off + disclaimer.
  3. **Originality** — similarity check vs. the site's own crawled content.
  4. **Brand voice + mandatory human approval** — nothing is "final" without an
     explicit approve action.
- DB: `content_drafts` table (id, projectId/url, inputs jsonb, draft, status,
  gates jsonb, timestamps). Drizzle migration.
- UI: multi-step Q&A form → generated draft with gate results → approve/reject.
- Pluggable `generateDraft()` — deterministic now; Claude-backed later.

## Feature 3 — Accounts + dashboard

Persist projects/reports/drafts per user.

- Auth: email + password (argon2/bcrypt) on the existing Postgres, session cookie
  (reuse the HMAC-cookie approach from the gate). No third-party auth service.
- DB: `users`, `sessions`, `projects`; link `report_requests` + `content_drafts`
  to a user/project.
- UI: signup/login, a dashboard listing projects with their latest scores, report
  history, and saved content drafts.
- Billing (Stripe) is explicitly deferred (not public yet).

## Sequencing

1 → 2 → 3. Each feature: TDD lib, then UI, then spec + code-quality review, commit.
Keep `main` (production) untouched until Phase 1 is approved for promotion.
